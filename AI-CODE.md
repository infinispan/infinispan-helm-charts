# Coding Instructions

## Tech Stack
* **Packaging:** Helm 3 chart (`apiVersion: v2`, `type: application`).
* **Templating:** Go templates / Sprig (standard Helm templating).
* **Target platforms:** Kubernetes (`kubeVersion: ">= 1.21.0-0"`) and OpenShift.
* **Deployed product:** Infinispan server (image `quay.io/infinispan/server`, tracked by `Chart.yaml` `appVersion`).

## Project Architecture

Top-level layout:

* **`Chart.yaml`** — Chart metadata. `version` is the chart version; `appVersion` is the Infinispan server `major.minor`.
* **`values.yaml`** — Default user-facing configuration. This is the chart's public API. Keys marked `# [USER]` are intended for end users to override.
* **`values.schema.json`** — JSON Schema validating user values. **Generated** from `values.schema.json.tpl` (see Generated Files).
* **`infinispan.conf`** — Branding properties consumed by `brand.sh` (upstream/community values).
* **`brand.sh`** — Generates the branded files from their `.tpl` sources.
* **`templates/`** — The Kubernetes resource templates:
  - `statefulset.yaml` — the Infinispan server StatefulSet (the core workload).
  - `service.yaml`, `ping-service.yaml`, `metrics-service.yaml` — Services (client access, discovery/ping, metrics).
  - `route.yaml` — OpenShift Route for external exposure.
  - `configmap.yaml` — rendered Infinispan server configuration.
  - `secret.yaml` — credentials / identities Secret.
  - `certificate.yaml`, `certificate-issuer.yaml`, `cert-keystore-secret.yaml` — cert-manager TLS integration.
  - `service-monitor.yaml` — Prometheus Operator ServiceMonitor.
  - `helpers.tpl` — shared named templates (naming, labels, helpers).
  - `_log4j2.xml.tpl` — logging configuration template.
  - `NOTES.txt` — post-install notes shown by Helm. **Generated** from `NOTES.txt.tpl`.
  - `tests/` — Helm test hooks (see `AI-TEST.md`).
* **`test/`** — Values snippets and manifests used by the CI test suite (see `AI-TEST.md`).
* **`documentation/`** — AsciiDoc documentation (see `AI-DOCS.md`).

## Generated Files — IMPORTANT

Three files are generated by `brand.sh` and **must not be edited directly**:

| Generated file          | Edit this source instead      |
|-------------------------|-------------------------------|
| `README.md`             | `README.md.tpl`               |
| `values.schema.json`    | `values.schema.json.tpl`      |
| `templates/NOTES.txt`   | `NOTES.txt.tpl`               |

After editing any `.tpl`, regenerate and commit both the source and the output:

```sh
./brand.sh infinispan.conf
git add README.md README.md.tpl values.schema.json values.schema.json.tpl templates/NOTES.txt NOTES.txt.tpl
```

CI (`.github/workflows/chart-verifier.yml`) runs `./brand.sh infinispan.conf` and **fails the build if the generated files are out of date**, so regenerating is not optional.

### `brand.sh` substitution caveats
`brand.sh` sources a properties file (`infinispan.conf` upstream) and `sed`-replaces placeholders in the `.tpl` files: `{brandname}`, `{website}`, `{serverImage}`, `{k8s}`, `{ingress}`.

- The `sed` commands have **no `/g` flag** — only the **first occurrence of each placeholder per line** is substituted. If a line needs the same placeholder twice, split it across lines.
- `{brandname}` → `Infinispan` for the upstream build. Downstream (RHDG) builds pass a different properties file, so always write branding through placeholders in the `.tpl`, never hardcode the product name.

## Common Commands

```sh
# Lint the chart
helm lint .

# Render templates locally without installing
helm template example-infinispan .

# Install into a cluster
helm install example-infinispan . -n <namespace> --set deploy.replicas=2

# Regenerate branded files (required after editing any .tpl)
./brand.sh infinispan.conf

# Package the chart (produces infinispan-<version>.tgz)
helm package .
```

## Development Standards

### values.yaml changes (backward compatibility)
* `values.yaml` is a public API consumed by existing user release values. Do **not** rename, remove, or change the type of an existing key without a strong reason — it breaks upgrades for existing releases.
* Add new options with safe defaults that preserve current behavior when unset.
* Keep `values.schema.json.tpl` in sync with new or changed values, then regenerate.
* Mark user-facing options with a `# [USER]` comment, following the existing style.

### Template conventions
* Reuse named templates from `templates/helpers.tpl` (naming, labels) rather than repeating logic.
* Gate optional resources (TLS, cert-manager, routes, ServiceMonitor) behind the relevant values with `{{- if ... }}` so they render only when enabled.
* Keep templates working on both Kubernetes and OpenShift; OpenShift-specific resources (Routes) must be conditional.

### Commit messages
* Reference the related GitHub issue using `#number` in the commit message.

### Git branches
* Name branches `issueid/short_summary` (for example `docs/155-certmanager-asciidoc`) and base them on `origin/main`.
